# 独立审查身份与原始证据

适用 Pre-Coding 独立审查及引用本规则的高风险复核。目的在于可核验来源，不承诺 Markdown 能做身份认证。

## 身份记录

列明主要编制模型及对本轮被审基线有实质编制贡献的其他模型：provider、产品显示模型名、可获得的模型标识/版本、运行时间、来源证据。人工编制可标 HUMAN_ONLY，但仍需独立模型审查。

Reviewer不得是被审范围的实质编制模型；改 Agent名、换会话/思考档位/角色提示不能改变身份。统一空格/大小写、已知别名与 provider 后比较身份；别名映射必须有来源，禁止凭字符串不同推断模型不同。同供应商的模型组合须事前由 Owner 登记在 allowlist，附可辨认不同底层模型的依据；证据不足不放行。不同供应商也不免除编制参与检查。

版本未向用户暴露时如实写 `NOT_EXPOSED`，附平台可见模型选择或调用元数据；不编造内部模型 ID/版本。若现有证据仍不能确认是另一个模型，输出 `IDENTITY_UNVERIFIED`，不能给有效 PASS。

## 原始报告与只读证据

保留审查服务/独立会话的原始报告 URL、评论 ID或只读导出文件，以及报告 hash、时间、审查包 hash、原始模型身份依据。保留最终审查结果和引用材料，不要求或收集隐藏思维链。SHA只能证明留存内容未变化，不能单独证明是谁生成。

不能由编制模型写一份“某外部模型已通过”代替原始报告。人工可以转贴外部模型的原文；必须标注转载、原始来源/模型证据和时间，不得当成新模型自己写入。私人材料外发须遵守项目的数据/授权策略，不在公开Issue粘贴凭据或客户内容。

Reviewer只读被审产物；记录前后基线，报告写入可以由单独写入执行者完成。不能一边实改合同一边审查自己的新版本。只读工具限制不可用时说明缺口，保留操作证据并核对基线；不得谎称已撤销写权限。

## 有效性核验

Technical Owner核验：身份与参与清单不冲突、真实原文存在、审查包匹配、覆盖范围完整、BLOCKER/MAJOR清零、Reviewer真实给出PASS。STRICT另附具名人工的来源核验说明；这可以和Gate批准在同一记录完成，不增加虚拟审批岗位。

无法核验则记录 REVIEW_EVIDENCE_UNVERIFIED，维持 Coding 禁止。不得由自述、文风、一个哈希或同一账号评论推断独立性。
