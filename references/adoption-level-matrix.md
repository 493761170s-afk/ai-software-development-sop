# 采用深度与各阶段质量下限

阶段 Skill 的准出必须同时满足本矩阵、已选 Profile 及交叉规则。文件存在、标题填满、勾选完成都不是质量证明。MVA/STANDARD/STRICT 调整材料深度，不省略阶段、独立模型审查或边界规则。

## 使用方式

项目用“产物/字段 → 唯一权威位置 → 负责人 → 审查证据”登记覆盖。相同信息引用一次即可；MVA 可以合在一份文档，STANDARD/STRICT 也不强制每个标题单独成文件。空模板、TODO、UNKNOWN 均不能替代本次交付必须明确的内容。

| 阶段 | MVA 最小产出与可检验标准 | STANDARD 增量 | STRICT 增量 |
|---|---|---|---|
| 1 项目定义 | 用户/调用方、目标结果、做/不做、依赖、风险、具名 Owner；目标能被观察验证 | 利益相关方、范围拆分、成功指标、依赖证据与决策记录 | 高影响风险、跨系统责任、数据/成本约束、风险接受权限有明确证据 |
| 2 需求 | 所有本期功能有稳定 ID、角色、输入/输出、正常/失败 AC；适用规则与 NFR 有测试口径 | PRD/功能需求/用例/规则可区分并互相追溯；状态、权限、异常、边界完整 | 数据/安全/并发/成本等高风险负向 AC；NFR 阈值、测量环境与风险覆盖可追溯 |
| 3 体验设计 | 每条核心任务从入口到结果；异常与不可用反馈明确；有 UI 时定义页面，无 UI 时定义调用行为 | 页面/调用清单、交互、文案、状态、设计版本及需求映射齐全 | 高风险路径、角色/数据边界、复杂恢复/部分失败的设计证据和独立检查 |
| 4 技术设计 | 模块边界、直接依赖合同、数据/状态、安全、失败恢复、测试和部署办法明确；必需方案已批准 | 数据字典/约束、接口/事件、第三方能力证据、迁移兼容、NFR方案与必要 ADR | 对安全/租户/AI/媒体/共享依赖的高风险验证；合同消费者清单、恢复与证据链 |
| 5 开发规划 | 本期完整 WBS；每项有输入/输出、来源、AC、测试、依赖、负责人、工作边界；唯一 Tracker | 按模块/页面/能力分工；明确估算单位、集成/提测任务与依赖；本期无遗漏 | 全量双向追溯；高风险任务独立审查/复测安排、共享消费者影响与发布依赖 |
| 1–5 独立审查 | 完整本期包、真实不同模型、只读、原始报告、BLOCKER/MAJOR=0、明确 PASS | 同左；不能用更多文档代替覆盖证据 | 同左，加具名人工对身份及来源核验的确认 |
| 6 开发 | 所有执行模式同一工作项与授权边界；自测、PR审查、集成和提测包 | 按合同并行、交接记录、模块责任与相关测试 | 高风险变更独立实现审查，禁止自改范围/标准 |
| 7 测试 | 环境/数据就绪、计划-执行对照、缺陷分诊、复测/回归、QA收尾；P0/P1独立复测 | 独立测试活动、探索性测试记录、严重度/优先级/响应目标和遗留风险 | 风险专项全覆盖；TEST_CORRECTION 由独立审查者确认，QA Owner签核 |
| 8 验收发布 | 产品/调用方验收、exact RC、必要环境验证、恢复步骤、明确发布批准及生产确认 | 部署/配置/迁移证据、业务UAT、监控与观察期、收尾 | 高风险恢复证明、独立QA/技术证据、共享消费者兼容与事故处理准备 |

## 不能按级别裁掉的内容

适用的权限/数据隔离、媒体不损坏源文件、AI敏感数据与副作用约束、幂等/失败恢复等由风险和 Profile 决定，不因 MVA 或 STANDARD 消失。高风险范围必须至少执行 STRICT 对应检查；Technical/QA Owner 记录局部提升，独立审查确认。低风险外围无需机械升级整个项目。

N/A 必须写理由、证据、Owner和影响范围，并由阶段审查核验。“还没做”“模型没读到”不是 N/A。没有 UI 可不产出 Figma，但 Stage 3 的调用流程/错误反馈不能跳过。生产系统不能把事故准备标 N/A 来逃避恢复责任。

## 合格与不合格示例

- 不合格 AC：“视频处理正常”。合格 AC：给定指定编码/帧率/时长样本，输出满足已批准格式和同步容差；取消/失败时源文件不变、临时产物可清理；每项映射用例。具体数值由项目批准，母 SOP 不代填。
- 不合格 NFR：“接口快且安全”。合格 NFR：项目明确负载、环境、响应分位数/错误率阈值、测量方法，以及未授权/跨租户读写的拒绝结果。
- 不合格任务：“完成前端”。合格任务：指定页面/交互和API版本，声明不改API/DB，包含正常/空/错/权限状态、自测和可验证输出。
- 不合格验收：“文件齐了，PASS”。合格验收：逐项引用已读取内容、版本与检查结果；关键未知项阻塞目标交付。
